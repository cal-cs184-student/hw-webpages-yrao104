Casteljau’s Algorithm + Implementation

De Casteljau’s Algorithm is a recursive method to evaluate Bezier curves using repeated linear interpolation through recursion. We implemented it by iterating through each of the points in the current level, determining the next set of points to interpolate, then passing it recursively to interpolate again.

Part 2: Bezier surfaces with separable 1D de Casteljau

Casteljau’s Algorithm with Bezier Surfaces + Implementation

De Casteljau’s Algorithm extends to 3D surfaces by running another set of times to break down the n x n vector of points to a single n long vector of points then proceeding as normal. Since control points now had a 2D vector of 3D points, we first iterated through each row with parameter u to get a vector of interpolated 3D points. We then ran a final set of interpolation based on this vector of 3D points with parameter v to achieve a single point on the Bezier curve.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

Area Weighted Norms

We compute the area weighted norms by iterating through each of the faces associated with the given vertex, finding each faces’ normal vectors and areas based on their three vertices, then adding these multiplied values together across all the faces to find the weighted norms for the vertex.

Part 4: Edge flip

Edge Flip Implementation + Debugging Tricks

We implemented edge flipping by going through each of the elements in the two faces associated with a given face, then modified them to correspond to the newly flipped edge. The faces and halfedges were built up for all of their elements, while each vertex and edge got their halfedge class variables updated. An interesting aspect of our implementation was how we reused existing faces and halfedges for the new edge rather than creating new ones, which was more efficient but required us to be more careful when reassigning variables.

Debugging Journey

Initially, when we flipped an edge, the color would turn black so we carefully looked through our code line by line and eventually found the source of our issue. We had set the next halfedge in the setNeighbors function call using edge->next() even though it pointed to the previous halfedge. By fixing this issue and ensuring that next pointed to the correct halfedges, our implementation worked.

Pre-Processing Observations - dae/cube.dae

dae/cube.dae + Pre-Splitting

Without pre-processing, the cube slowly morphs into a sphere-like shape with bulges to the top right and bottom left. Once we add a split in the initial edge across the square’s diagonal, the original shape is symmetrical, allowing the final shape to be symmetrical as well. This initial symmetry is beneficial since as the cube becomes subdivided into smaller and smaller triangles, each of these triangle’s neighbors divisions will be evenly mirrored across the shape since the original shape is symmetrical, maintaining the shape’s overall symmetry.
