Overview

In this homework, we implemented a physically-based cloth simulation using a system involving point masses and springs. We generate point masses and springs, utilize numerical integration for motion, and take care of collisions with other objects. We also implemented shaders to render the cloth with much more realistic lighting. After completing this homework, we learned how minor modifications in the algorithm can make such a big difference both visually and in terms of performance. For instance, techniques like varying simulation parameters such as spring constants, density, and damping, can make a huge difference in the appearance of the cloth.

Part 3: Handling Collisions With Other Objects

Handling Collisions with Spheres and Planes Implementation

We handled collisions with spheres by checking if the point mass intersects with the sphere or is inside the sphere using the radius. If so, we calculate the tangent point on the sphere surface and push the point mass to the surface of the sphere using the last position of the point mass, the origin, radius of the sphere, and add a correction vector multiplied by (1-friction). Similarly, we handled collisions with planes by checking if a point mass moves from one side of the plane to the other side in a time step. Once again, if so, we calculate the tangent point on the plane and push the point mass to a point slightly above it. Then, we let the point mass's new position be the last position plus a correction vector multiplied by (1-friction).

Part 4: Handling Self-Collisions

Implementation

At every time step, we check to see if there are any collisions between all point masses in the cloth. To check if two point masses collide, first we precompute a hashmap mapping all point masses to a unique 3D box. Then, comparing a point mass with all other point masses within the same 3D box, if their distance is sufficiently close, we classify the masses as colliding and correct the point mass’s position vector.

Part 5: Shaders

What is a Shader Program?

A shader program is an optimized, specialized system that allows shading in a render to be computed directly using the GPU rather than the CPU. It operates in two main stages, the vertex shader followed by the fragment shader. The vertex shader breaks down the 3D geometry of vertices in shapes and translates them to 2D pixels that will be displayed on screen. The fragment shader takes the data from the vertex shader and combines it with information from light sources and textures to determine the actual color and shading of objects in the render.

Blinn-Phong Shading

This model of shading breaks down how light interacts with objects in a rendering into three main components - ambient, diffuse and specular. The ambient layer consists of indirect light that scatters around a room, the diffuse layer consists of how bright certain parts of an object are depending on how close they are to and the angle it faces the light source, and the specular layer determines how shiny an object looks. By summing these three components, shading can be completed much quicker while still yielding realistic results.
